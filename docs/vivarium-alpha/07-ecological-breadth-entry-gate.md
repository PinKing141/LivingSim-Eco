# 07 - Ecological Breadth Entry Gate

## Purpose

Prevent content expansion from beginning before the observer game is proven.

Major breadth work is expensive because every new species, biome or ecological system multiplies testing, balancing, visual, UI and save-data complexity.

Breadth therefore has an entry gate.

---

## Breadth is locked until Alpha proves

- players can create/load worlds without help,
- navigation and observation are comfortable,
- graphs/overlays answer ecological questions,
- history and lineage create understandable stories,
- the visual direction is locked,
- watchability has been tested in long sessions,
- performance remains inside budgets,
- the Alpha Exit Gate passes.

---

## Candidate breadth areas

Once unlocked, candidates include:

- additional herbivore niches,
- additional predator niches,
- specialised scavengers,
- migration depth,
- richer plant ecology,
- disease/parasites,
- wildfire/disturbance,
- aquatic ecosystems,
- seasonal specialists,
- additional climate regimes,
- niche construction,
- more advanced geographic isolation,
- eventual speciation.

This list is a backlog, not a commitment.

---

## Admission test for every new system

A proposed addition must answer:

1. What new ecological interaction does it create?
2. Which existing systems does it interact with?
3. What new player-observable story can it produce?
4. How will the player understand it?
5. What are the performance/storage costs?
6. What new regression tests are required?
7. Does it need new art/UI/audio/content pipelines?
8. Can it be tested independently before entering the full ecosystem?

If the only answer is “more variety,” it should not enter the roadmap yet.

---

## Breadth production pattern

Use the same pattern for every major content/system addition:

`Design hypothesis → controlled prototype → isolated viability test → simulation regression → observation/UI integration → multi-seed soak → content lock`

Do not add multiple unproven ecological systems simultaneously.

---

## Vertical-slice rule

Before producing many examples of a content type, build one production-quality example.

Examples:

- one complete disease model before many diseases,
- one complete aquatic food chain before many fish,
- one complete fire ecology loop before multiple disturbance systems,
- one complete specialised migration strategy before many migratory species.

This is the same content-pipeline discipline used in large productions: prove the pipeline before scaling the asset count.

---

## Content budget

For each breadth milestone define caps for:

- number of new species,
- number of new behaviours,
- number of new biome/resource types,
- save-data increase,
- performance cost,
- visual assets,
- QA matrix expansion.

Do not let content count expand invisibly.

---

## Regression requirement

Every breadth addition must rerun:

- determinism tests,
- save/load continuation,
- benchmark seed cohort,
- ecological long-runs,
- performance captures,
- observer readability scenarios,
- history/event detection regression.

Existing worlds should not become incomprehensible merely because more systems exist.

---

## Gate pass condition

Ecological breadth begins only when:

- Alpha has passed its exit gate,
- the observer experience is stable enough to explain new systems,
- the visual production pipeline is locked,
- the first breadth milestone has a capped scope,
- every addition has a measurable ecological purpose.

After this point, breadth becomes the next major product roadmap leading toward Beta.
